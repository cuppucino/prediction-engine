# Local OANDA demo engine — implementation specification

User authorization: build locally, four strategy agents for EURUSD and XAUUSD, direct OANDA MT5 demo orders, Telegram updates. No frontend or live-account support. New Telegram bot. User reports server `OANDA_Global-Demo1`, balance 10,000, likely USD; terminal must verify these rather than infer currency. Earlier research is background, not a requirement to simulate first.

## Architecture

Python 3.11+ standard-library service: four deterministic strategy workers, SQLite execution journal/outbox, shared risk coordinator, Telegram long polling, authenticated loopback HTTP. MQL5 Expert Advisor in installed desktop MT5 sends market/account snapshots and executes guarded commands. Broker passwords stay inside MT5. macOS MT5 uses bundled Wine; no Windows VPS and no OANDA REST substitution. One EA on one chart handles both instruments. Source code and build instructions must work even before credentials are supplied.

Agents use completed bars only, immutable versioned signals, fixed initial SL/TP attached atomically to each market order. No averaging down, trailing, manual position modification or forced close commands in v1. All four agents may enter trades, one position per symbol across all agents. Conflicts are journaled and deterministic priority rotates with the bar. SL/TP are broker-held; program sleep/disconnection stops new entries but does not remove existing stops. Stop execution can exceed intended risk.

## Bridge contract v1

POST `/v1/snapshot`, `Authorization: Bearer <32+ character local token>`, JSON, max 2 MiB. `version:1`, `utc` epoch seconds, `connected:bool`, `trade_allowed:bool`, `history_complete:bool`; `account:{login:int,server:str,company:str,currency:str,demo:bool,balance:number,equity:number,margin_free:number}`. `positions:[{ticket:int,identifier:int,symbol:str,magic:int,side:'BUY'|'SELL',volume:number,sl:number,tp:number,profit:number,risk:number}]` where risk is loss from current liquidation price to stop in account currency (zero if stop profitable, -1 if unavailable). `orders:[{ticket:int,symbol:str,magic:int}]`. `deals:[{ticket:int,order:int,position_id:int,magic:int,entry:int,symbol:str,volume:number,profit:number,commission:number,swap:number,fee:number,time:int}]`. Include all trade deals in history (up to 2000; set history_complete=false on overflow or failed history selection). Deal times may be broker times; do not use them as UTC scheduling inputs. `symbols:{EURUSD:{bid,ask,tick_age,point,tick_size,digits,stops_level,trade_mode,bars:{M15:[bar],H1:[bar],H4:[bar]}},XAUUSD:{...}}`. A bar is `{time,open,high,low,close}`; chronological order, start_pos=1, 240 completed candles. Bar time is broker epoch (identity/order only); no UTC/session conversion needed for these strategies. `tick_age` seconds measured against broker server time. Missing/synchronizing data fails closed.

Each symbol also supplies `bar_age:{M15:number,H1:number,H4:number}`: seconds from last completed candle close to broker clock, -1 if unavailable. This prevents fresh ticks from legitimizing stale history. The coordinator requires an age between zero and one period plus 60 seconds.

Response plain text `WAIT` or exactly 14 pipe-separated fields:
`OPEN|id|login|symbol|BUY/SELL|sl|tp|risk_cash|expires_utc|magic|max_spread|max_slippage_price|equity_floor|max_margin_fraction`.
id: 24 lowercase hex characters. magic: unique per command in [700000000000,800000000000). All numbers finite and positive. expiry <= now+15 sec. SL/TP are absolute prices. max_slippage_price also bounds drift from most recent submitted tick. market spread bound derived from signal stop distance. margin fraction default .20 (total used margin after OrderCheck <= equity*.20). Equity floor from persisted UTC-day baseline and daily loss limit. Only exact configured symbols.

POST `/v1/result` JSON `{id,status,retcode,order,deal,volume,price,detail}`. status `filled`, `rejected`, or `uncertain`. Response `OK`. Persistent pending EA acknowledgement retries before any next snapshot or new command. API result is idempotent; duplicate cannot change a settled result. Broker deal reconciliation remains authority. Python marks dispatch in SQLite BEFORE HTTP response. It never redelivers a command. Missing response/ack => unresolved command blocks all entries until matching deal evidence or explicit operator review. A dispatched command with no proven outcome is never automatically cleared by expiry.

EA requirements: demo trade mode EXACT, expected login and server exact, company contains OANDA, connected/trade allowed, hard-coded two-symbol allowlist, command syntax bounds, UTC expiry, fresh ticks, stop distance/tick normalization, spread and drift checks, account equity floor, no position/order on same symbol, respect all foreign account exposure. Calculate volume with OrderCalcProfit in account currency at adverse allowed entry price, floor to volume step, reject below min, validate SL/TP order flags and trade direction. OrderCheck then OrderSend once. Persist command claim using terminal global variables plus flush BEFORE sending. Treat timeout/unknown retcode as uncertain, never retry a broker order. No unprotected fallback order. Persist acknowledgement across restarts. Demo identity rechecked immediately before execution. Global mutex prevents simultaneous EA executors within a terminal. Disable orders by default via input switch; attach/configure then enable once setup is complete, not per trade.

## Coordinator

Pin account login and exact server in local config, verify demo flag and OANDA company. Defaults risk .0025 equity per trade, max total open stop risk .005 equity, UTC daily drawdown .02; drawdown latches pause until next day and explicit resume. Maximum two positions (one each). Unknown positions, pending orders, missing SL, incomplete history, invalid/nonfinite data, stale tick/snapshot, unconfirmed orders, or account changes block entry. Persist baseline, signal evaluations, unique (agent/version/symbol/bar), command with signal/risk, deals and notifications. Risk limits enforced again at terminal where possible. Start paused each process boot. Resume via authenticated local CLI or allowlisted Telegram private chat, only with fresh eligible snapshot. Resume has no per-trade approval. Status explains disconnection, pauses, unresolved commands, and eligibility.

Telegram sends startup/readiness, accepted/rejected/uncertain orders, fills, exits and daily scorecards. Durable outbox with bounded retry/backoff. Long polling persists update offsets. Commands `/status`, `/agents`, `/positions`, `/stats`, `/pause`, `/resume`, `/help`; allowlisted private chat/user only, discard stale control messages. No arbitrary Python or broker commands, no group reader. Pause only stops new entries. Never log bot tokens or account passwords. New bot setup manual through BotFather, token saved locally with restrictive permissions.

## Deterministic rule versions

Use ATR14 simple mean true range, EMA20/50 seeded with SMA, sufficient 120+ completed bars. Exact final rules in `docs/STRATEGIES.md` and strategy tests. Trend H4 EMA20/50 crossover with SL2ATR / TP3ATR; breakout M15 close crossing prior20-bar high/low with SL1.5ATR / TP3ATR; pullback H1 in EMA20/50 trend, prior close opposite EMA20 and current recross with SL1.5ATR / TP3ATR; range M15 prior20 close mean ±2 standard deviations recross in low-trend regime abs(EMA20-EMA50)<.5ATR, SL1.5ATR / TP at prior mean (minimum reward:risk .8). All versions initial experimental hypotheses, not validated profitability. Do not call scores confidence/probability. Same rules tested separately for gold and FX.
